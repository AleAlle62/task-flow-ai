task-flow-ai · repository map

Six phases, one writer

A coding task is split into six phases. Each one runs as a separate agent, reads only the files the phases before it left behind, and gets handed only the permissions its job needs. Exactly one of the six can change your code. Every folder in this repository exists to keep that sentence true.

THE FOUR AREASWhat the repository is made of

Four areas, and the dependencies only ever point one way. The files you edit know nothing about the engine; the engine knows nothing about the browser.

FolderWho it is forWhy it exists
agents/ you One markdown file per phase: the frontmatter declares what it may do, the body is its instructions.
pipelines/ you One YAML file per pipeline: which phase runs when, what it reads, where it stops for a human.
cli/ the tool All the TypeScript — reads those files, runs the phases, keeps the result.
web/ the tool The app served during a run, so you can watch it and answer a gate from a browser.
skills/ other agents A SKILL.md that lets an agent invoke this pipeline the way it invokes anything else.
dist/ · web-dist/ nobody Build output. Generated, never edited.

THE FLOWWhat actually happens during a run

Phases never talk to each other. Each one writes a file, and the next one reads it — which is what lets a run be reread tomorrow, resumed after a crash, and watched by something that is not this process.

THE ENGINEInside cli/

Each folder answers one question, and the split is what keeps the answers from leaking into each other.

FolderWhat it decidesWhy it is separate
cli/model/ The words everything else agrees on: capabilities, phases, run state. Nothing here reads a file or validates anything, so everyone can depend on it.
cli/pipeline/ Turning your YAML and markdown into those words — and refusing them when they are wrong. Every “your file is broken” message lives here, and only here.
cli/providers/ Translating capabilities into one agent CLI's own flags. The only place a vendor's tool name is written down. Swapping the agent underneath is this folder and nothing else.
cli/run/ Running a pipeline: order, gates, inputs, artifacts, corrections. The largest area, split again below.
cli/commands/ What each terminal command does, one file per command. Thin on purpose: parse arguments, call the engine, print.
cli/server/ The local HTTP server the browser talks to during a run. A run works with the server switched off, so this folder is optional by construction.
cli/errors/ What a failure is, and whether trying again could plausibly help. Retrying a dropped connection is right; retrying an expired session wastes a person's afternoon. One table decides which is which.
cli/util/ Small things with no opinions: spawning, globbing, frontmatter, arguments. Anything here could be copied into another project unchanged.
Inside cli/run/What it holds
phases/ Running one phase, and the rules around it: what it may write, when work goes back for a second round.
gates/ Where a run stops and waits for a person, and how the answer is remembered so it is never asked twice.
inputs/ Assembling what a phase gets to read — the task, earlier artifacts, the current diff.
store/ One directory of plain files per run: artifacts, state, event log. This is what makes a run resumable and watchable.
orchestrator.ts Sits above those four and decides only what happens next.
Inside web/src/What it holds
components/One component per thing on screen: the flow, the artifacts, the gate, the log.
stores/The run as the browser sees it, fed by the event stream.
api/The HTTP client, and the shapes it expects back from cli/server/.
lib/ · composables/Small helpers: rendering markdown, keeping a clock ticking.

THE BOUNDARYOne rule, checked in four places

Exactly one phase may change your code. It is not a note in a prompt — it is declared, checked, enforced and verified again, at four different moments.

If you change one thing in this repository, change it knowing which of the four places you are standing in.

Loosening the frontmatter of an agent file changes what a phase is allowed to ask for. Loosening rules.ts changes what a pipeline is allowed to describe. Loosening the provider changes what the agent is actually handed — and that is the only one of the three the model can feel.

There is a fifth mark this drawing does not show, because it sits around all of them: cli/providers/claude-sandbox.ts, which is where every phase's shell loses the network, the ability to read your credentials, and the ability to write to the files that decide how your machine starts. Deciding which commands may run says nothing about what those commands can reach.
